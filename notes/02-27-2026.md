## Task: Fix Per-Channel Highlight Compression Issue

### Problem
The highlight compression algorithm in `x3f_process.c` was compressing each color channel independently. This meant that if the yellow channel clips, only that channel would be compressed while others remained unchanged, resulting in bold/muddy colors in clipped regions instead of a smooth roll-off to white.

### Solution Implemented
Modified the highlight compression in `x3f_process.c` (around line 1052-1082) to use uniform scaling when highlights clip:

**Key Changes:**
1. Calculate `x_max` across all 3 channels to detect when highlights are clipping
2. Only apply uniform compression when `x_max > highlight_knee` (2.0)
3. For clipped highlights:
   - Apply the tone curve + compression to `x_max` to get `y_max`
   - Calculate `scale_factor = y_max / x_max`
   - Apply this same scale factor to ALL channels equally
4. For shadows/mid-tones: maintain per-channel processing

**Benefits:**
- Preserves color ratios in clipped regions
- Prevents bold/muddy colors in blown highlights
- Maintains hue while managing intensity
- Smooth roll-off to white instead of per-channel distortion

### Testing Results
Tested on `_P2M0937.X3F` which has significant clipped regions:
