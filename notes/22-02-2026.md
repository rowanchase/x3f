**Key Processing Pipeline (x3f_process.c):**
1. Load X3F file
2. Get black level from masked pixels (DarkShield areas)
3. Get max raw levels
4. Calculate intermediate bias and scaling
5. Preprocess data (scale to 14-bit intermediate)
6. Fix bad pixels (interpolation)
7. Denoise (optional)
8. Color conversion (raw -> XYZ -> target color space)
9. Apply spatial gain (color compensation across frame)
10. Apply gamma/LUT

## GitHub Issues Review (Kalpanika/x3f upstream repo)

### CRITICAL: Issue #117 - Green tint in shadows (DP Merrills) since v0.57

**Status:** Open
**Opened:** May 24, 2020
**Author:** geni1105

**Description:**
- Version 0.56 works fine, but 0.57 introduces strong green tint in shadows for DP Merrill X3Fs
- Red channel is underexposed according to raw histogram comparison (0.57 vs 0.56)
- Does NOT happen with DP Quattros (only affects Merrill cameras)

**Root Cause Identified (see PR #120):**
The right "shielded" area on DP1M, DP2M, DP3M is NOT truly shielded and contains light-sensitive data with a linear increasing exposure gradient. Using this area for black level calculation produces incorrect black levels.

**Visual Evidence:**
User provided RawDigger screenshots showing the shielded region has a gradient, not uniform black.

### CRITICAL: PR #120 - Proposed fix for green tint (NOT MERGED)

**Status:** Open (not yet merged as of Feb 2026)
**Author:** Alex-Vasile
**Opened:** March 2023

**The Fix:**
```c
// In src/x3f_process.c, get_black_level() function
// Add RIGHT (=3) to use array and disable it for Merrill cameras

#define RIGHT 3

// Add this check:
if (!strcmp(cammodel, "SIGMA DP1 Merrill") || 
    !strcmp(cammodel, "SIGMA DP2 Merrill") || 
    !strcmp(cammodel, "SIGMA DP3 Merrill")) {
    use[RIGHT] = 0;  // Don't use right shielded area for black level
}
```

**Key Insight:**
- The right shielded area in Merrill sensors has a linear exposure gradient
- This area is NOT truly optically shielded
- Using it for black level calculation causes underestimation of black level
- Result: shadows appear with green tint (red channel most affected)

### Analysis

1. **Overall darker output** - All channels have negative mean errors:
   - Red: -53.85 (darkest)
   - Green: -38.98
   - Blue: -47.29

2. **Errors increase with luminance**:
   - Shadows: MAE 24.38
   - Midtones: MAE 47.96  
   - Highlights: MAE 76.02

3. **Max error of 255** - Some pixels are completely wrong

### Interpretation

This pattern is **consistent with the PR #120 black level issue**:
- Using right shielded area (which has a gradient) underestimates black level
- Lower black level → darker output (negative mean errors)
- Effect more visible in highlights (where signal is higher)
- Red channel most affected (explains green tint in shadows)
