### CRITICAL: Issue #117 - Green tint in shadows (DP Merrills) since v0.57

**Status:** Open
**Opened:** May 24, 2020
**Author:** geni1105

**Description:**
- Version 0.56 works fine, but 0.57 introduces strong green tint in shadows for DP Merrill X3Fs
- Red channel is underexposed according to raw histogram comparison (0.57 vs 0.56)
- Does NOT happen with DP Quattros (only affects Merrill cameras)

**Root Cause Identified (see PR #120):**
The right "shielded" area on DP1M, DP2M, DP3M is NOT truly shielded and contains light-sensitive data with a linear increasing exposure gradient. Using this area for black level calculation produces incorrect black levels.

**Visual Evidence:**
User provided RawDigger screenshots showing the shielded region has a gradient, not uniform black.

### CRITICAL: PR #120 - Proposed fix for green tint (NOT MERGED)

**Status:** Open (not yet merged as of Feb 2026)
**Author:** Alex-Vasile
**Opened:** March 2023

**The Fix:**
```c
// In src/x3f_process.c, get_black_level() function
// Add RIGHT (=3) to use array and disable it for Merrill cameras

#define RIGHT 3

// Add this check:
if (!strcmp(cammodel, "SIGMA DP1 Merrill") || 
    !strcmp(cammodel, "SIGMA DP2 Merrill") || 
    !strcmp(cammodel, "SIGMA DP3 Merrill")) {
    use[RIGHT] = 0;  // Don't use right shielded area for black level
}
```

**Key Insight:**
- The right shielded area in Merrill sensors has a linear exposure gradient
- This area is NOT truly optically shielded
- Using it for black level calculation causes underestimation of black level
- Result: shadows appear with green tint (red channel most affected)

## Deep Dive into Brightness/Contrast Difference (Afternoon Session)

### Key Finding: Non-Linear Ratio Across Luminance

The ratio between our output and SPP's output is NOT constant:
- Shadows (luma 0.0-0.1): ratio ~1.3 in linear space
- Midtones (luma 0.2-0.3): ratio ~2.1
- Highlights (luma 0.5-1.0): ratio ~3.1

This non-linear relationship suggests **SPP applies a tone curve** not just brightness adjustment.

### Processing Trace

Traced through the processing mathematically:
1. Raw data mean: [107.58, 192.29, 261.84] per channel
2. After black subtraction: [76.45, 161.07, 230.68]
3. After scaling to intermediate (14-bit): [355.87, 355.61, 335.38]
4. After normalization: [0.0188, 0.0396, 0.0568]
5. After conv_matrix: [0.0864, 0.0965, 0.0625] (linear)
6. After gamma: [0.325, 0.343, 0.277] → 8-bit: [82, 87, 70]

This matches our actual output (mean ~75), confirming processing is correct from code perspective.

### Linear Space Comparison

- Our linear mean: ~0.07 (after processing)
- SPP linear mean: ~0.18 (calculated from reference)
- Ratio in linear space: ~2.6x

### Conversion Matrix Analysis

The conv_matrix (after ISO scaling of 2.0x):
```
  9.24   -4.06    1.29
 -8.17    8.15   -1.28
  5.25  -11.32    7.27
```

For neutral gray input, this produces values > 1 and negative values (expected for color conversion).

### DNG vs TIFF ISO Handling

In DNG output (x3f_output_dng.c line 352):
```c
double baseline_exposure = log2(capture_iso/sensor_iso);
TIFFSetField(f_out, TIFFTAG_BASELINEEXPOSURE, baseline_exposure);
```

This stores ISO scaling as metadata for raw converters to apply.

In TIFF output (x3f_process.c line 755):
```c
x3f_scalar_3x3_mul(iso_scaling, raw_to_rgb, conv_matrix);
```

This bakes the ISO scaling directly into the color matrix.

### Hypothesis

**SPP likely applies a custom tone curve (S-curve) for contrast enhancement.**

Evidence:
1. Issue #74 mentions "TIFF output is low contrast and soft"
2. ACR/Lightroom apply +50 brightness and +25 contrast by default
3. The increasing ratio with luminance is characteristic of an S-curve

### Possible Solutions

1. **Apply a contrast enhancement curve** - Match SPP's tone curve
2. **Disable ISO scaling for TIFF** - Let exposure match SPP's interpretation
3. **Apply exposure compensation** - Calculate offset needed

## Jim Kasson Blog Post Analysis

User pointed to: https://blog.kasson.com/the-last-word/more-on-foveon-image-processing/

**Key findings from the article:**

1. **SPP applies aggressive sharpening that cannot be disabled**
   - Even with sharpness at -2 (minimum), MTF boost is still applied
   - Contrast at Nyquist frequency is 50%+ vs expected ~10%
   - This is done "by design" for the "Foveon look"

2. **Raw data is clean**
   - The raw composite from RawDigger shows smooth MTF curve
   - No inherent sharpening in the sensor data
   - Oversharpening comes entirely from SPP processing

3. **Monochromatic mode is cleaner**
   - In monochrome mode with sharpness -2, the gratuitous sharpening is reduced
   - Suggests the color processing path adds more "enhancement"

**Implications for our work:**

SPP is NOT producing a "neutral" output - it's applying:
1. A tone curve (S-curve for contrast)
2. Aggressive sharpening (MTF boost)
3. Possibly other "looks"

This means **x3f_extract's output is technically more "neutral"** - it's producing linear output with standard sRGB gamma, while SPP applies a "house curve" for visual appeal.

**Decision point:** Should x3f_extract:
- A) Match SPP's "look" (add tone curve + sharpening)?
- B) Produce neutral output for editing (current behavior)?

Option A would make direct comparison match, but Option B is arguably more correct for a raw converter.

## Transfer Function Analysis (Detailed)

Tested the relationship between our output and SPP's output in linear space:

| Output Range | SPP Range | Ratio |
|--------------|-----------|-------|
| 0.003 | 0.027 | 9.7x |
| 0.013 | 0.038 | 3.0x |
| 0.021 | 0.052 | 2.5x |
| 0.036 | 0.086 | 2.4x |
| 0.068 | 0.171 | 2.5x |
| 0.092 | 0.241 | 2.6x |
| 0.116 | 0.320 | 2.8x |

**Curve fit results:**
- Power curve: `SPP = 3.41 * x3f^1.11`
- Exposure+Contrast: exposure=2.7x, contrast=1.02

This is characteristic of an **S-curve tone adjustment**:
- Shadows: ~9.7x lift (toe of curve)
- Midtones: ~2.5x (linear region)
- Highlights: ~2.8x (shoulder of curve)

The ISO scaling (2.0x) we're applying is close but not enough - SPP adds an additional ~1.35x multiplier on top of ISO scaling.

### Hypothesis

SPP applies a "film-like" tone curve on top of sRGB gamma:
1. Lift shadows (toe)
2. Boost midtones
3. Gentle shoulder for highlights

This is similar to what Adobe Lightroom does with its "Baseline Exposure" for various cameras.

### Rotation Issue Identified

Files with ROTATION metadata ≠ 0 need rotation:
- ROTATION="90": Rotate 90° CW (files 30, 33, 36)
- ROTATION="270": Rotate 90° CCW (files 34, 35)

**This is a separate issue from exposure compensation.**

### Rotation Implementation Plan

The X3F files have ROTATION metadata:
- "0" - No rotation needed
- "90" - Rotate 90° clockwise
- "270" - Rotate 90° counter-clockwise

SPP applies this rotation when outputting TIFFs. x3f_extract needs to:
1. Read ROTATION metadata from CAMF
2. Apply rotation before writing output TIFF
3. Rotate by 90° CW or CCW as needed

Reference files already have rotation applied (orientation tag = 1).
