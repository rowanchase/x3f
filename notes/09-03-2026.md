# Journal: 09-03-2026 - Color Bias Detection Tool & White Paper Analysis

## Summary
Created a new analysis tool to detect color bias in images and used it to quantify the color drift issue in Merrill camera outputs.

## Tool Created: count_color_bias.py

### Purpose
Calculate how many pixels in an image have an overall colour bias (R, G, or B dominant) versus being neutral (white, grey, or black).

### Algorithm
For each pixel:
1. Calculate mean = (R + G + B) / 3
2. A pixel is biased if one channel exceeds mean + threshold AND the other two are below mean
3. Threshold: 512 for 16-bit, 2 for 8-bit (configurable)

### Features
- Auto-detects 8-bit vs 16-bit TIFFs
- 3x3 regional breakdown
- Configurable threshold via `-t` flag
- Regional analysis can be disabled with `--no-regional`

### Location
`tools/count_color_bias.py`

## White Paper Analysis Results

Tested on _P2M1182 (photo of white paper - used for color drift detection):

| Image | Neutral | R-biased | G-biased | B-biased |
|-------|---------|----------|----------|----------|
| SPP Reference | 100.0% | 0.0% | 0.0% | 0.0% |
| Our output | 0.1% | 0.0% | 0.0% | **99.9%** |

### Interpretation
- SPP reference correctly produces neutral grey for white paper photograph
- Our output has a **severe blue cast** across the entire image (99.9% B-biased)
- This confirms the global color balance issue identified in earlier analysis

### Root Cause (from 07-03-2026 analysis)
The issue is NOT spatial uniformity - existing spatial gain is working correctly (we're more uniform than SPP with max corner delta 13.14 vs 20.84).

The issue is **global color balance**:
- R channel: 127 vs 147 (mean) = -14% (too dark)
- G channel: 121 vs 147 (mean) = -18% (too dark)  
- B channel: 145 vs 146 (mean) = correct

This is a color matrix issue - the `WhiteBalanceColorCorrections` from metadata is being misused as a conversion matrix.
